# Key Concepts

This page defines the core terminology used throughout Minke's documentation.

## Asset Types

### DFI — Deterministic Future Income

A future income stream where the amount and schedule are fixed and known in advance. Examples:
- Token vesting schedules (cliff + linear)
- SAFT / investor allocation tranches
- Node license emission schedules
- Mining reward agreements

DFI is the primary asset class Minke Phase 1 handles. Because the schedule is deterministic, no oracle is needed.

### VFI — Variable Future Income

A future income stream where the amount depends on external factors — utilisation rates, price feeds, governance decisions. Examples:
- Liquid staking yields (stETH)
- AMM LP fees
- Lending protocol interest

VFI requires Minke Phase 2 (Yield Token). Phase 1 VT is not suitable for VFI.

## Protocol Primitives

### VT — Vesting Token

A fungible ERC-20 that represents a 1:1 claim on the underlying token at vesting maturity. VTs are:
- Minted 1:1 at tranche creation (no upfront fee)
- Tradable on any DEX as standard ERC-20
- Stakeable to earn pro-rata vesting unlocks in Phase 1
- Redeemable 1:1 for underlying at or after Phase 2

### YT — Yield Token (Phase 2)

A future token type designed for VFI streams where yield is variable. Not yet live — see the roadmap for planned release.

### Tranche

A single VestingToken deployment representing one vesting position. Each tranche has:
- A specific underlying token
- A fixed `vestStart` and `vestEnd`
- Its own accumulator (`accVTPerShare`) tracking pro-rata unlocks

### BuybackPool

An early exit facility deployed alongside each VestingToken. VT holders can convert VTs into the underlying token at any time during Phase 1 by paying a protocol fee (e.g. 5%). The BuybackPool sources its T from the vault as tokens vest per the schedule.

## Staking Mechanics

### accVTPerShare

A global accumulator that tracks the total underlying tokens unlocked per staked VT. Updated each time `checkpointVesting()` is called. Increases monotonically as the vesting schedule progresses.

### userDebt

A per-user baseline that records the `accVTPerShare` value at the time of the user's last interaction (stake, unstake, or claim). The difference between the current `accVTPerShare × stakedVT` and `userDebt` is the user's pending claimable amount.

### Checkpoint

A call to `checkpointVesting()` that reads the current vested amount from the schedule and updates `accVTPerShare`. Anyone can call it at any time — it is a permissionless, idempotent operation.

## Economic Terms

### Present Value (PV)

The market-determined value today of a future cash flow. In Minke, VTs trade at a discount to par (1 underlying) until maturity. The discount reflects time value and risk.

### Excess Tokens

The underlying tokens remaining in the vault after all Phase 1 claims. These become available for 1:1 redemption in Phase 2 by outstanding VT holders.

### Protocol Fee

A fee (e.g. 5%) charged when a VT holder converts VTs into the underlying token via the BuybackPool. The fee is not charged at deposit, on staking rewards (`claimT()`), or on Phase 2 redemption (`redeemVT()`).

<Callout type="note">
The fee rate is fixed at contract deployment. There is no admin key that can change fee parameters post-deploy.
</Callout>
