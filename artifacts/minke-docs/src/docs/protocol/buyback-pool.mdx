# BuybackPool

The BuybackPool is a liquidity facility funded by the e.g. 5% protocol fee. It provides Phase 1 exit liquidity and creates a price floor for VTs within a tranche.

## Purpose

In Phase 1, VT holders who want to exit early have two options:

1. **Sell on an AMM** — sell VTs at the market-determined discount
2. **Convert via BuybackPool** — exchange staked VT positions for a pro-rata share of the BuybackPool's underlying holdings

The BuybackPool is not an AMM. It does not require liquidity providers or a counterparty. It holds the protocol fee tokens and allocates them proportionally to VT holders who choose to exit via it.

## How It Works

At tranche creation, the protocol fee (e.g. 5%) of deposited tokens is transferred to the BuybackPool:

```
Deposited:    1,000,000 TOKEN
BuybackPool:     50,000 TOKEN  (e.g. 5%, funded once at creation)
VestingToken:   950,000 TOKEN
```

During Phase 1, a staker can call:

```solidity
function convertViaBuyback(uint256 vtAmount) external;
```

This function:
1. Checks the caller's staked VT balance
2. Calculates the pro-rata share of BuybackPool the caller is entitled to:

```
payout = vtAmount × (poolBalance / totalStakedVT)
```

3. Burns the staked VT
4. Transfers `payout` TOKEN to the caller

<Callout type="warning" title="BuybackPool vs AMM">
BuybackPool conversions are not the same as selling on an AMM. The BuybackPool pays from a fixed reserve — once it is depleted, no further BuybackPool conversions are possible. AMM liquidity is not affected.
</Callout>

## Price Floor Mechanics

Because the BuybackPool always holds real underlying tokens, it creates an implicit floor price for VTs. Any rational VT holder will sell via the BuybackPool rather than an AMM if the AMM price falls below:

```
BuybackPool price = poolBalance / totalStakedVT
```

In practice, this means VT market prices tend to stay above the BuybackPool floor, creating a healthy price discovery range.

## BuybackPool and AMM Interaction

The BuybackPool and AMM coexist and complement each other:

- **AMMs** offer full liquidity at market-determined prices
- **BuybackPool** offers a guaranteed minimum floor backed by real assets

As VT maturity approaches, the AMM price converges to par (1:1 with underlying) and the BuybackPool floor becomes less relevant. In Phase 2, the BuybackPool is not used — `redeemVT()` provides direct 1:1 redemption.

## BuybackPool Depletion

If the BuybackPool is exhausted before Phase 2 begins, `convertViaBuyback()` reverts. VT holders can still:

- Sell VTs on AMMs
- Stake and claim Phase 1 pro-rata unlocks
- Wait for Phase 2 and call `redeemVT()`

<Callout type="info">
The BuybackPool is designed to be a supplementary exit, not the primary one. The primary exits are AMM trading and Phase 2 redemption.
</Callout>

## Technical Notes

The BuybackPool contract is deployed alongside each `VestingToken` by `VestingFactory`. Key parameters:

```solidity
address public immutable underlyingToken;
address public immutable vestingToken;
uint256 public poolBalance;     // decreases as conversions occur
```

The `poolBalance` is public and readable on-chain at all times, providing full transparency into available exit liquidity.
