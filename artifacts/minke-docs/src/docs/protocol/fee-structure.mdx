# Fee Structure

Minke charges a protocol fee only when VT holders use the BuybackPool to convert their VTs into the underlying token (T) before maturity. There is no upfront deposit fee.

## When the Fee Applies

The protocol fee (e.g. 5%) is charged at the moment of BuybackPool conversion:

```
VT holder calls convertViaBuyback(100 VT)
  → receives e.g. 95 T  (payout after fee)
  → 5 T  → protocol treasury  (e.g. 5% fee)
```

**Depositing does not incur a fee.** Depositing 1,000,000 TOKEN mints exactly 1,000,000 VT.

## What the Fee Is NOT

- **Not an upfront deposit fee** — 1,000,000 TOKEN in = 1,000,000 VT out
- **Not a staking fee** — `claimT()` distributes pro-rata vesting unlocks with no deduction
- **Not a Phase 2 redemption fee** — `redeemVT()` at maturity is always 1:1 with no fee

## Why the Fee Is on BuybackPool Conversion

Holders who use the BuybackPool are getting instant liquidity before their vesting schedule has ended. The protocol fee compensates the system for providing that early exit option. Holders who wait until Phase 2 pay no fee.

## Comparing Exit Paths

| Exit Path | Protocol Fee | Speed |
|---|---|---|
| Sell VTs on AMM | None (market discount applies) | Instant |
| BuybackPool conversion | e.g. 5% | Instant |
| Stake and claim via `claimT()` | None | Ongoing during Phase 1 |
| Phase 2 redemption (`redeemVT`) | None | At or after maturity |
| OTC vesting desk (off-chain) | 15–40% spread | Days to weeks |

## Fee Finality

The fee rate (e.g. 5%) is set at tranche deployment and stored in the contract. No function exists to change it after deployment. Users can verify this by reading the contract's immutable variables on any block explorer.

<Callout type="note">
Future protocol versions may introduce governance-controlled fee tiers. Any changes would apply to new tranches only — existing tranches are immutable.
</Callout>
